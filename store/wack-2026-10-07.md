## Дополнительное замечание

Анализатор обнаружил ссылки на API запуска процессов в библиотеках Microsoft .NET,
WPF / Windows Forms и в SunShift, а также строковые совпадения с именами вроде
`cmd`, `bash`, `MSBuild` в сторонних и системных библиотеках.
Наличие строки или ссылки на API само по себе не доказывает запуск этой программы.

Просмотрены все вызовы `Process.Start` в исходниках SunShift. Их два:
кнопка исходного кода открывает `https://github.com/GodRayine/SunShift`,
кнопка параметров геопозиции открывает `ms-settings:privacy-location`.
Оба используют обработчик URI Windows через `UseShellExecute=true`.
SunShift не запускает cmd, PowerShell, bash, MSBuild, драйверы или установщики.
Удалять необходимые библиотеки .NET ради строковых совпадений не стали.

Для настольных приложений Microsoft относит этот тест к дополнительным:
он не определяет итог допуска в Store. Совместимость с Windows в S mode
этим отчётом не подтверждается.
[Критерии Desktop Bridge](https://learn.microsoft.com/en-us/windows/uwp/debug-test-perf/windows-desktop-bridge-app-tests).

## Пределы проверки

WACK выполнил файловые тесты MSIX (`FileOnlyTests=True`). Пакет для Store остался
без локальной подписи. Установка, обновление, удаление, реальный запрос геопозиции,
смена обоев и автозапуск установленного приложения ещё требуют проверки.
PASS WACK не означает, что Microsoft уже приняла приложение.

Полный XML: `../artifacts/store-checks/wack-store.xml`.
Машинный итог: `../artifacts/store-checks/wack-summary.json`.
Лог запуска: `../artifacts/store-checks/wack-run.log`.
Повторная проверка выполняется через `scripts/Run-Wack.ps1` из Windows PowerShell
от администратора; необходимо выбрать новый путь отчёта.
